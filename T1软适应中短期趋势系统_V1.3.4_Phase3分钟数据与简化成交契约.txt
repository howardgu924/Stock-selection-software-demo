T+1软适应中短期趋势系统 V1.3.4
Phase 3分钟数据与简化成交契约
版本日期：2026-07-14

一、版本目的

V1.3.4不修改Phase 1的OpportunityScore，也不修改Phase 2的MarketOverlay、背离、RiskOverlay、ExecutionGate和EmergencyMarketGate。

本版本冻结：

1. 5分钟K线数据契约；
2. 指定执行时点直接成交；
3. 买卖成交资格检查；
4. 费用计算接口；
5. 跨午休和跨交易日的下一执行K线；
6. 成交成功、失败和可重试状态。

本阶段不实现PositionSizing、T+1持仓状态机、ExitEngine、PendingSell状态机、数据库、网页或报告。

二、建议模块

- 数据库与网页；

- T+1持仓状态机；
- ExitEngine与PendingSell；
- 报告。

三、分钟时间契约

1. 所有分钟时间使用Asia/Shanghai。
2. bar_start表示5分钟K线开始时刻。
3. 无时区时间按Asia/Shanghai解释；混合其他时区或无法统一时返回INVALID。
4. 合法bar_start：
   - 09:30至11:25，每5分钟一根；
   - 13:00至14:55，每5分钟一根；
   - 全天共48根；
   - 午休期间不得产生K线。

五、分钟K线有效性

有效K线必须满足：

1. symbol可规范化；
2. trade_date与bar_start日期一致；
3. bar_start属于合法A股5分钟时刻；
4. open/high/low/close可转换为有限正数；
5. high >= max(open, close, low)；
6. low <= min(open, close, high)；
7. volume为有限数值且volume >= 0；
8. trade_status与limit_status属于允许枚举。

不得自动填补、前向填充或使用相邻K线替代。

六、重复K线

同一symbol、trade_date、bar_start：

- 必需字段完全一致：确定性去重；
- 任一必需字段不同：INVALID，原因conflicting_duplicate_bar:<bar_start>；
- 不得使用keep="last"。

七、成交价格

1. 所有成交价格直接使用执行K线Open。
2. 不使用High、Low、Close、Volume、Amount、VWAP、买卖盘、滑点、成交容量、部分成交或排队。
3. 修改执行K线High、Low、Close或Volume不得改变成交价格和成交资格。
4. 成交必须使用原始未复权价格。

八、交易规则快照

FillEngine由调用方传入TradingRuleSnapshot：

exchange
board
security_type
effective_date
buy_lot_size
partial_sell_lot_size
full_exit_odd_lot_allowed
price_tick

Phase 3不自行计算涨跌停价，直接使用limit_status。

九、费用规则快照

调用方传入FeeRuleSnapshot：

commission_rate
minimum_commission
buy_transfer_fee_rate
sell_transfer_fee_rate
buy_settlement_fee_rate
sell_settlement_fee_rate
stamp_tax_rate

费用公式：

BuyCommission =
max(GrossAmount × commission_rate, minimum_commission)

SellCommission =
max(GrossAmount × commission_rate, minimum_commission)

BuyFees =
BuyCommission
+ GrossAmount × buy_transfer_fee_rate
+ GrossAmount × buy_settlement_fee_rate

SellFees =
SellCommission
+ GrossAmount × sell_transfer_fee_rate
+ GrossAmount × sell_settlement_fee_rate
+ GrossAmount × stamp_tax_rate

CashRequired =
GrossAmount + BuyFees

NetProceeds =
GrossAmount - SellFees

使用Decimal计算，金额ROUND_HALF_UP保留人民币分。

十、买入成交

1. 买入信号10:00确认。
2. 同日10:05执行。
3. 成交价为10:05 K线Open。
4. requested_qty由调用方传入，FillEngine不缩量。

成功条件：

- 10:05 K线存在且有效；
- trade_status = normal；
- limit_status不是limit_up或unknown；
- requested_qty > 0；
- requested_qty是buy_lot_size整数倍；
- CashAvailable >= CashRequired；
- 规则快照有效。

允许limit_down买入。

失败条件：

- suspended；
- unknown状态；
- limit_up；
- K线缺失、冲突或Open非法；
- 数量非法或不符合交易单位；
- 现金不足；
- 规则快照非法。

失败时整笔不成交，不追价，不自动改到10:10。

十一、卖出成交

1. 按指定执行K线Open成交。
2. requested_qty由调用方传入。

成功条件：

- K线存在且有效；
- trade_status = normal；
- limit_status不是limit_down或unknown；
- requested_qty > 0；
- requested_qty <= PositionQty；
- requested_qty <= SellableQty；
- 数量满足部分卖出或全部退出规则；
- 规则快照有效。

允许limit_up卖出。

部分卖出：

requested_qty < PositionQty时，必须为partial_sell_lot_size整数倍。

全部退出：

requested_qty = PositionQty时：
- full_exit_odd_lot_allowed=true：允许全部零股；
- 否则仍须满足partial_sell_lot_size。

失败时整笔不成交。

十二、执行类型

FillRequest包含：

ENTRY_BUY
HARD_EXIT
SOFT_EXIT
REPLACEMENT_EXIT
ORDINARY_REDUCTION

规则：

- ENTRY_BUY：固定10:05；
- HARD_EXIT：信号K线完成后的下一根合法交易K线；
- SOFT_EXIT、REPLACEMENT_EXIT、ORDINARY_REDUCTION：14:30判断，14:35执行。

十三、下一执行K线

resolve_next_execution_bar(signal_bar_start, trading_calendar)：

- 普通时段：下一根5分钟K线；
- 11:25之后：同日13:00；
- 14:55之后：下一交易日09:30；
- 跨日必须使用交易日历，不使用自然日加一；
- 下一执行K线缺失：FAILED，原因missing_execution_bar；
- 不继续寻找更晚K线；
- 是否重试留给Phase 4。

十八、版本结论

V1.3.4采用最简成交模型：

指定执行时点存在有效Open，且不受停牌、对应方向涨跌停、未知状态、资金、持仓、SellableQty和交易单位限制时，整笔按Open成交。

不引入滑点、容量、排队、部分成交或追价。

Phase 3完成后必须先做只读审查，验收通过后才能进入Phase 4。
